# Cognitive Yield Monitor｜认知收益监测器

**一个实验性的开源 Agent Skill：帮助 AI 分辨对话是在推进、进行有价值的探索，还是陷入重复。**

> AI 可以一直回答，即使对话早已没有实质进展。如果它能意识到这一点，并帮助人选择更好的下一步呢？

[English](README.md) · [中文核心 Skill](SKILL.zh-CN.md) · [英文核心 Skill](SKILL.md) · [对照实验方案](docs/EXPERIMENT_PROTOCOL.md) · [项目介绍文章（中文）](docs/launch-post.zh-CN.md)

## 这个项目想解决什么？

大多数对话系统都擅长继续回答。Cognitive Yield Monitor 加入一个简单却重要的问题：

**下一次回答，是否可能帮助用户朝真正的目标取得进展？**

目标不是不惜一切代价缩短对话。情绪支持、刻意练习、创意探索和研究讨论，对“进展”有不同定义。有时重复是有帮助的；有时不确定性正在孕育新问题；有时讨论确实在原地打转，需要换一种方法。

这个 Skill 会要求模型关注用户目标、已有洞察、未解决问题、证据和最近的实际变化。必要时，它可以建议验证主张、寻找反例、切换分析框架、把想法变成行动、整理结论，或有意识地继续探索。

## 五种对话状态

| 状态 | 含义 |
|---|---|
| **ADVANCING（正在推进）** | 出现有意义的新洞察、证据、推论、应用或目标相关进展。 |
| **PRODUCTIVE UNCERTAINTY（生产性不确定）** | 尚无定论，但有用的问题、张力或区分正在形成。 |
| **DIMINISHING RETURNS（边际收益递减）** | 最近多轮实质内容反复表达已有观点，却缺少有意义的新证据或进展。 |
| **READY TO CLOSE（可以收束）** | 用户的目标看起来已经得到充分满足。 |
| **INSUFFICIENT EVIDENCE（证据不足）** | 上下文太短、含混或不完整，无法负责任地判断。 |

触发提醒的门槛刻意设置得比较保守。单次回答重复，不足以判定整场对话陷入循环。提醒应说明重复在哪里、承认判断存在不确定性，并提出具体下一步。最终决定权始终属于用户。

## 快速开始

1. 克隆或下载本仓库。
2. 将 `SKILL.zh-CN.md` 或 `SKILL.md` 加载到支持 Agent Skills 的宿主，或适配为该平台支持的自定义指令。
3. 在一场有一定深度的讨论中直接问：**“请评估目前这场对话的边际认知收益。”**
4. 如果讨论似乎陷入循环，可以换一种操作：验证核心主张、寻找反例、定义可测量的问题、做出决策，或总结目前真正成立的结论。

### 平台兼容性与限制

不同平台和产品版本对 Skill 的支持与安装方式不同，请参考 [OpenAI Skills 文档](https://developers.openai.com/api/docs/guides/tools-skills) 和 [Anthropic Agent Skills 文档](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)。

Skill 是一组指令，**不是自主运行的后台进程**。它不能静默检查所有未来消息，也无法访问宿主没有提供的历史上下文。它能否运行，取决于宿主是否加载并遵循它。

## 设计原则

- **进展取决于目标：** 按用户真正想完成的事情评估，而不是只追求新颖。
- **先看证据，再打断：** 措辞重复本身并不能证明讨论陷入循环。
- **保护生产性不确定：** 问题暂时没有答案，不代表讨论没有进展。
- **区分对话模式：** 不把情绪整理、刻意练习或发散式创作误判成浪费。
- **尊重用户自主权：** 提供建议，不接管选择；用户决定继续后，不反复唠叨。
- **诚实描述能力：** 这是模型判断，不是对认知的科学测量。

## 不要只相信它，要评估它

仓库包含初始定性案例，以及一份建议的对照实验方案：

- [初始评测案例](evals/cases.json)
- [实验流程与结果报告模板](docs/EXPERIMENT_PROTOCOL.md)
- [示例对话](references/examples.md)
- [定性评估标准](references/rubric.md)

当前案例是**用于测试的样例，不是基准测试结果**。在使用匹配案例对比基线和启用 Skill 的模型，并人工检查输出之前，不应宣称它已被证明有效。误报（过早提醒）与漏报（未发现循环）应分开衡量。

运行 Python 3.9+ 结构校验：

```bash
python scripts/validate_project.py
```

该脚本检查仓库结构和评测数据格式，不评估模型行为。

## 路线图

1. **先验证想法：** 在不同对话模式下，对比启用和未启用 Skill 的表现。
2. **研究失败模式：** 找出过早提醒、漏掉循环，以及把不确定性误当停滞的案例。
3. **邀请外部案例：** 收集去除隐私信息后的真实案例。
4. **有证据再扩建：** 如果提示词式 Skill 不够，再考虑平台专用中间件或独立监测 Agent。

## 如何贡献

最有价值的贡献不一定是新功能，而是能挑战当前设计的案例：一次误报、一次漏报、一次有价值的重复，或一个正确答案其实是“证据不足”的场景。详情见 [`CONTRIBUTING.md`](CONTRIBUTING.md)。
